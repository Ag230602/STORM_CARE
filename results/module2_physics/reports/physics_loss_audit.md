# PI-GNO Physics Loss Audit

Date: 2026-07-16

## Scope

This report documents the physics-loss investigation for `model/physics`. All
metrics below were regenerated by rerunning scripts after code changes. CSVs and
figures were not edited manually.

## Root Causes and Fixes

1. Graph finite differences used the wrong edge direction.
   - Source: `model/physics/graph_builder.py`
   - Root cause: `edge_index` is stored as `[dst, src]`, but the operator unpacked
     it as `[src, dst]`, reversing finite-difference directions and scattering
     messages to the wrong nodes.
   - Fix: unpack as `dst, src`, keep destination scatter semantics, and compute
     derivatives using physical edge distances.

2. Spatial derivative scaling was dimensionally wrong.
   - Source: `model/physics/graph_builder.py`
   - Root cause: gradients and Laplacians used a global normalized-grid scale
     instead of dividing each edge difference by physical edge distance.
   - Fix: added `edge_dist_phys`; gradients use `1 / d_phys`, Laplacians use
     `1 / d_phys^2`.

3. `R_cont` was exactly zero by construction.
   - Source: `model/physics/physics_kernels.py`
   - Root cause: the continuity threshold was `(50 m/s * dt)^2 / channels`, which
     is enormous for a 6-hour step, so realistic predictions never exceeded it.
   - Fix: replaced the thresholded ReLU with a differentiable normalized increment
     penalty over channel-specific physical scales.

4. Pressure terms used hPa as if they were Pa.
   - Source: `model/physics/physics_kernels.py`
   - Root cause: pressure-gradient force terms used MSLP anomalies in hPa directly.
   - Fix: convert pressure channels from hPa to Pa before pressure-gradient terms.

5. Physics losses were too small to influence optimization.
   - Source: `model/physics/config.py`, `model/physics/physics_kernels.py`
   - Root cause: raw SI residual MSE values were many orders of magnitude smaller
     than field MSE; default weights left `L_total ≈ L_data`.
   - Fix: normalize residuals by characteristic physical scales and rebalance
     physics weights.

6. Physics finite-difference time step did not match the synthetic data interval.
   - Source: `model/physics/config.py`
   - Root cause: `dt_physics` was 3600 seconds while synthetic samples advance by
     one 6-hour step.
   - Fix: set `dt_physics = 6 * 3600` seconds.

7. Synthetic track displacement had a unit mismatch.
   - Source: `model/physics/train.py`
   - Root cause: steering motion omitted the seconds conversion and mapped degree
     displacement onto normalized grid spacing.
   - Fix: compute displacement from meters per second and seconds, then convert to
     grid cells using the configured domain width.

8. Validation omitted several residuals.
   - Source: `model/physics/train.py`
   - Root cause: validation logged only a subset of residuals, making it impossible
     to verify all constraints after retraining.
   - Fix: validation CSVs now include `R_adv`, `R_diff`, `R_mass`, `R_wp`,
     `R_cont`, and `R_nrg`.

## Scientific Conclusion

The corrected physics constraints now influence optimization: `L_phys` is
non-negligible, every residual has gradient connectivity, and `R_cont` is no
longer identically zero.

On the corrected 20-epoch CPU demo, the full-physics model improves physical
consistency across all tracked validation residuals, most strongly for diffusion,
wind-pressure balance, mass conservation, and temporal continuity. The no-physics
ablation retains better predictive error on this small synthetic demo. Therefore,
the supported claim is:

> The corrected PI-GNO physics loss improves physical consistency in the demo
> retraining, while predictive accuracy remains better for the no-physics
> ablation under the current short demo configuration.

The manuscript should not claim predictive-accuracy improvement from this demo
unless a longer or differently balanced experiment is rerun and supports that
claim.

## Remaining Limitations

- The 6-hour residual step intentionally matches the synthetic sample interval,
  but the logged CFL number is greater than 1. This is a residual-evaluation
  limitation, not a hidden training failure; it should be disclosed if these demo
  results are used in the paper.
- These results are CPU-demo results, not a full-scale NeurIPS/ICLR experiment.
  Any paper table should identify the run configuration used to generate it.
